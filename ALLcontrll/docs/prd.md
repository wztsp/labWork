### 2.2 关键技术事实（决定方案选型）

| 维度 | 实测结论 | 对需求的影响 |
|---|---|---|
| **服务发现** | Nacos 运行时全线禁用（启动脚本 `-Dspring.cloud.nacos.discovery.enabled=false`）；网关硬编码 IP；Feign 为死代码。**无真实注册中心** | 「服务状态」不能依赖注册中心，需**自带可配置服务注册表 + 主动健康检查轮询** |
| **Actuator** | 全仓库 pom.xml 无 `spring-boot-starter-actuator` 依赖，application.yml 无 `management.endpoints` 配置。`/actuator/health` **不可用**（指南中提及但实测不存在） | 健康检查采用 **TCP 端口探测** 为主，可选 **可配置 HTTP 健康探测 URL**（如某已知 GET 接口返回 200 即视为存活） |
| **日志配置** | 无 logback-spring.xml / logback.xml；application.yml 仅设 `logging.level`；无 `logging.file.name` | 日志为 Spring Boot 默认控制台输出，由启动脚本 PowerShell 重定向落盘 |
| **日志文件** | 路径 `lis-system/logs/`，命名 `lis-{name}.out.log`（stdout）与 `lis-{name}.err.log`（stderr）；另有少量游离日志（`report-service.log` 等）与 JVM 崩溃日志（`hs_err_pid*.log`） | 上传日志文件后按标准 Spring Boot 行格式解析 |
| **日志格式** | 标准行：`2026-07-31T17:28:11.321+08:00  INFO 16212 --- [lis-service-report] [main] com.lis... : 消息`；级别 INFO/DEBUG/WARN/ERROR；异常堆栈含 `Exception`/`Caused by`/`at ...` | 解析规则按此格式提取：时间戳、级别、线程、logger、消息、堆栈 |
| **前端部署** | 无 nginx 配置；开发用 `vite dev`（端口 3000，代理 `/api` → 8080）；生产 `npm run build` → `dist/` 静态文件 | 「前端服务状态」= 其服务端口（3000 或静态服务器端口）是否可达 |
| **既有日志能力** | LIS `LogController` 仅管理数据库表 `SysAuditLog`（操作审计日志），**不涉及运行时错误日志** | 新系统的「异常日志」与既有审计日志无重叠，可独立实现 |

## 三、产品目标

**一句话**：为 LIS 系统提供一个独立部署的运维后台，让管理员一站式查看前后台服务运行状态并便捷分析异常日志。

1. **状态可视**：集中展示 14 个后端服务 + 1 个前端的实时存活状态与历史记录，无需登录各机器逐一 `netstat`。
2. **日志可查**：通过上传日志文件，快速筛选、定位 ERROR/异常堆栈，缩短故障定位时间。
3. **独立无侵入**：与 LIS 代码零耦合、零修改、可独立部署，不影响现有业务系统稳定性。
4. **运维提效**：提供仪表盘汇总与自动刷新，降低日常巡检人力成本。

## 五、需求池

### P0 — Must Have（必须实现）

| ID | 需求描述 | 验收标准 |
|---|---|---|
| P0-1 | **可配置服务注册表**：内置默认 14 后端 + 1 前端清单（名称/类型/主机/端口/可选健康URL），支持在界面或配置文件中增删改。 | ① 默认载入上表 15 条；② 可新增/编辑/删除服务条目并持久化；③ 重启后配置不丢失。 |
| P0-2 | **服务状态总览页**：列表展示全部服务，含名称、类型(前端/后端)、端口、状态徽标(在线/离线/未知)、最后检测时间、响应耗时(ms)。 | ① 状态徽标颜色正确；② 离线服务置顶/高亮；③ 显示最后检测时间与耗时。 |
| P0-3 | **健康检查引擎**：默认 TCP 端口探测（连接成功=在线）；可选为服务配置 HTTP 健康探测 URL（GET 返回 2xx=在线）。 | ① TCP 探测超时≤3s 判离线；② 配了 HTTP URL 时优先用 HTTP；③ 探测并发执行，全量检测≤10s。 |
| P0-4 | **手动刷新 + 自动刷新**：支持手动「立即检测全部」按钮；支持自动刷新开关与间隔配置（如 10/30/60s）。 | ① 手动刷新即时重检并更新；② 自动刷新按设定间隔循环且可暂停；③ 刷新中显示 loading。 |
| P0-5 | **异常日志上传与解析**：支持选择/拖拽上传 `.log` 文本文件；按 Spring Boot 标准行格式解析为结构化记录（时间戳/级别/线程/logger/消息/是否含堆栈）。 | ① 上传成功后展示解析条数；② 解析失败（非文本/超大）给出明确提示；③ 单文件上限（待确认，建议 50MB）。 |
| P0-6 | **异常日志列表与筛选**：列表展示时间/级别/服务/logger/消息摘要；支持按级别(ERROR/WARN)、时间范围、关键字筛选；按级别高亮。 | ① 筛选条件组合生效；② ERROR 行红色高亮；③ 大列表分页/虚拟滚动不卡顿。 |
| P0-7 | **异常日志详情**：点击某条打开详情抽屉，展示完整消息与异常堆栈（含 `Caused by`/`at ...`），支持复制。 | ① 堆栈完整未截断；② 一键复制全文可用。 |

## 六、UI 设计稿（文字 + 结构描述）

> 整体：左侧导航 + 顶部栏（标题/自动刷新开关/当前时间）+ 主内容区。风格简洁，状态用色彩语义（绿=在线、红=离线、灰=未知）。

│ LIS 运维后台      [自动刷新 ▼30s]  [立即检测]  2026-07-31 18:00 │
├─ 概览卡片 ──────────────────────────────────────────────┤
│ [在线 13]  [离线 2]  [总数 15]  [健康率 86.7% ⚠]          │
├─ 服务列表（表格）───────────────────────────────────────┤
│ 服务名        类型   端口  状态   最后检测      耗时  操作 │
│ lis-gateway   后端   8080  ●在线  18:00:01     12ms  详情 │
