## node:sqlite 替换 better-sqlite3 —— 后端成功启动

因 `better-sqlite3` 原生模块在本机无法编译（缺 MSVC）且 GitHub 预编译被沙箱阻断，
将后端数据库驱动从 `better-sqlite3` 切换到 Node 22 内置的 `node:sqlite`（`DatabaseSync`）。

**改动文件**：
- `server/src/db/connection.ts`：import 换 `node:sqlite`；`new Database()` → `new DatabaseSync()`；
  `db.pragma()` → `db.exec('PRAGMA ...')`；新增 `wrapDatabase()` 为 `DatabaseSync` 实例添加
  `pragma()` 和 `transaction()` 兼容方法（手动 BEGIN/COMMIT/ROLLBACK），上层 Repository 代码零改动。
- `server/src/types/node-sqlite.d.ts`：新建，`@types/node@20` 不含 `node:sqlite` 类型，提供最小声明。
- `server/package.json`：移除 `better-sqlite3` + `@types/better-sqlite3`；dev 脚本改为
  `tsc --watch & node --experimental-sqlite --watch dist/index.js`（因 tsx 缺 esbuild 平台二进制，
  改用 tsc 编译 + node 直接运行）；engines 改 `>=22`。
- `server/vitest.config.mts`：更新注释（移除 better-sqlite3 引用）。

**验证结果**：
- 后端在 http://localhost:8900 成功启动，15 条种子数据写入正常
- API `/api/services`、`/api/dashboard/summary` 返回正确 JSON
- 前端代理 `localhost:8901/api/*` → `localhost:8900` 正常，**500 错误已消除**
- 95 单测全绿（server 81 + web 14），零回归
- `node:sqlite` 的 `@`命名参数 + 对象绑定、`run()` 返回 `{changes, lastInsertRowid}` 均与 better-sqlite3 兼容

**注意事项**：
- `node:sqlite` 需 `--experimental-sqlite` flag（Node 22+）
- dev 脚本中 `&` 为 bash 语法（tsc watch 后台 + node 前台），cmd.exe 下需改用 `concurrently`

## 启动命令自动配置（目录扫描匹配）—— 快速模式

团队 `software-auto-startcmd`，走快速模式：工程师(实现) → QA(验证)。

**功能**：用户指定根目录，系统递归扫描（最大深度3）可执行文件，按服务名自动匹配生成启动命令，勾选后批量应用。

**扫描文件类型**：jar→`java -jar`、package.json(含start脚本)→`npm start`、docker-compose.yml→`docker-compose up -d`、exe/bat→直接路径
**匹配逻辑**：精确(文件名去扩展名==服务名)>前缀(文件名以服务名开头)>包含(关键词匹配)；同优先级取最短文件名
**关键词提取**：服务名按`-`分段，过滤通用前缀(lis/service)和过短分段(<2字符)，按长度降序

**文件变更**：2 新建 + 5 修改 = 7 文件
- 新建：`server/src/services/startCommandDetector.ts`（核心检测+应用逻辑）、`web/src/components/AutoDetectDialog.tsx`（配置弹窗）
- 修改：server types + routes（POST /auto-detect, POST /apply-detected）、web types + api client + OverviewPage（新增"自动配置"按钮）

**测试**：160 用例全绿（server 146 含 QA 新增 startCommandDetector 30；web 14），零回归
**API 验证**：auto-detect 正确扫描5文件匹配3服务（prefix/exact），apply-detected 批量更新成功，错误目录返回400
**路由注册顺序**：/auto-detect 和 /apply-detected 必须在 /:id 之前，避免被参数路由捕获
