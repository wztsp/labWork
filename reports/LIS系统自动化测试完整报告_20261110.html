1. 测试概述

本次测试面向 LIS 系统两条主线业务：常规检验（申请→采集→送检→签收→上机→仪器回传→报告）与微生物检验（申请→接种→培养基核收→鉴定/药敏→规则评估→发布），每条主线各构造 10 条真实业务数据，全流程通过接口驱动执行，并对关键状态流转、分支场景与质控链路进行校验。

3. 测试范围、方法与数据构造

3.1 测试范围

  • 常规检验：检验申请、试管分组（合管）、条码生成、标本采集、送检、签收、上机（核收）、仪器结果回传、结果落库、审核出报告、报告发布
  • 微生物检验：申请与条码、标本前处理、接种（培养皿条码生成）、培养基核收、革兰氏染色、细菌鉴定、药敏试验、耐药/专家规则评估、多级报告发布；分支：血培养接种-报警-终判、阴性报告、仪器鉴定药敏回传
  • 质量控制：常规生化质控（Westgard 判定）、微生物室内质控（7 类质控物品）
  • 逆向操作：取消采集/送检/签收、撤销核收、撤销审核、取消条码；标本拒收/退费/作废；微生物取消最终报告、删除鉴定/药敏、撤销培养基核收、作废培养基条码、删除质控记录；以及各类非法逆向操作的拦截校验

3.2 测试方法

采用接口级自动化：脚本登录获取 JWT 后，按真实业务顺序调用 REST 接口，逐步断言返回码、状态字段与落库结果；每步失败记录错误上下文但不中断后续用例，最终汇总通过率。仪器结果采用与后端 ASTMParser 一致的 ASTM E1394 报文构造（H/P/O/R/L 记录）。

3.3 数据构造规则

  • 常规：每人 1 条申请，项目为「血常规（CBP，testItemId=9）」，10 例对应 10 份标本
  • 微生物：轮转 8 种培养项目（一般细菌培养/尿液培养/血液培养/分泌物培养/脑脊液培养/胸腹水培养/粪便培养/厌氧菌培养），标本类型与培养方案匹配
  • 仪器回传：血常规 10 项指标（WBC、RBC、HGB、HCT、MCV、MCH、MCHC、PLT、NEUT%、LYMPH%），带单位与参考区间
  • 雪花 ID（如微生物项目 ID）统一以字符串传输，避免 JavaScript 数值精度丢失

4. 常规检验全流程测试

4.1 流程与状态机

标本状态流转：0 已申请 → 1 已采集 → 2 已送检 → 3 已签收 → 4 已核收（上机）→ 5 检测中 → 6 已报告。测试中对非法跳转（未采集直接送检/签收/核收、重复采集/送检/签收/核收）进行了拦截校验。

4.2 接口时序

  1. POST /api/sample/orders/receive 创建检验申请（拆分一申请一项目）
  2. GET /api/sample/orders/page 查询申请，取 visitId / patientId / 明细
  3. GET /api/sample/tube-groups?visitId= 计算试管分组（合管）
  4. POST /api/sample/batch 生成标本条码（初始状态 0）
  5. PUT /api/sample/collect → 状态 1；PUT /api/sample/deliver → 2；PUT /api/sample/signoff → 3
  6. GET /api/sample/receive/precheck 核收预检；PUT /api/sample/receive 上机核收 → 4
  7. POST /api/instrument/data/receive?instrumentId=3&brand=MINDRAY 仪器 ASTH 结果回传
  8. GET /api/report/technician/{sampleId} 校验结果落库（10 项）
  9. PUT /api/report/technician/{sampleId}/audit 审核 → 标本状态 6，报告发布

5. 微生物检验全流程测试

5.1 流程与状态机

标本流：申请 → 采集条码 → 采集 → 送检 → 签收 → 接种（按培养方案生成培养皿条码）→ 培养基条码核收。
培养皿状态：0 未核收 → 1 已核收；2 已作废。
报告状态：1 初步报告（核收自动创建）→ 2 鉴定报告 → 3 最终报告；阴性报告保存后直接进入最终报告。

5.2 接口时序

  1. 申请与条码：同常规流程（/api/sample/orders/receive → /tube-groups → /batch → /collect → /deliver → /signoff）
  2. POST /api/micro/sample-plate/generate 按检验项目 + 标本类型匹配培养方案，生成 2~3 个培养皿条码
  3. POST /api/report/micro/receive-by-plate?plateBarcode= 培养基条码核收，自动创建初步报告（status=1）
  4. PUT /api/report/micro/{id}/gram-stain 革兰氏染色结果
  5. POST /api/report/micro/{id}/organisms 细菌鉴定（大肠埃希菌 EC）
  6. POST /api/report/micro/{id}/sensitivities 药敏结果（氨苄西林 R / 头孢曲松 S / 左氧氟沙星 I）
  7. POST /api/report/micro/{id}/evaluate-rules 与 GET /rule-hits 耐药规则评估
  8. PUT /api/report/micro/{id}/publish?targetStatus=2 → 鉴定报告；targetStatus=3 → 最终报告
  9. 分支接口：/api/micro/blood-culture/inoculate|{id}/alarm|{id}/final、PUT /{id}/negative、POST /api/report/micro/instrument-results/by-barcode

8. 缺陷与修复记录

序号问题现象与影响修复内容
1启动脚本 Java 路径失效start-all-services.ps1 硬编码旧版工具链 JRE 路径，服务无法启动改为读取 JAVA_HOME，缺省回退至本机 JDK 17
2微服务 jar 不可执行各服务 target 下为普通 jar（无 Main-Manifest），单独启动报「没有主清单属性」改用单体聚合包 lis-monolith-fresh.jar 统一启动（内置全部模块）
3单体 Bean 同名冲突reagent 与 system 模块均存在 SysConfigController / SysConfigServiceImpl / SysConfigMapper，聚合启动抛出 ConflictingBeanDefinitionException为 reagent 侧指定独立 Bean 名（reagentSysConfigController、reagentSysConfigService），Mapper 重命名为 ReagentSysConfigMapper（对应表 lis_sys_config）
48090 端口被占用优酷客户端占用 8090（认证服务端口）且自动重启停止优酷进程释放端口；生产部署建议改用独立服务器或调整端口规划
5取消最终报告后发布时间残留微生物「取消最终报告」将状态回退为 2（鉴定报告），但 publish_time / audit_time / auditor_id 未被清空（MyBatis-Plus updateById 默认忽略 null 字段），报告详情仍显示发布时间，状态与时间字段不一致改为 LambdaUpdateWrapper 显式 set null 清空审核/发布时间（MicroReportServiceImpl#revokeFinalReport），重新打包后 10/10 逆向用例、254/254 断言全部通过
6取消条码后报告残留（风险）常规标本撤销至「已申请」后执行取消条码会物理删除标本，但此前生成的检验报告仍保留在报告列表中（逆向测试两轮累计产生 20 份无标本报告），存在临床误查风险建议：撤销审核/撤销核收时同步作废或删除对应报告，或在取消条码前校验是否存在报告并阻断。本次仅记录风险，未改动业务代码

问题 1~4 为环境/部署类问题；问题 5 为逆向操作相关的业务逻辑缺陷，已修复并回归通过；问题 6 为数据一致性风险，建议后续版本处理。修复后 20 条正向全流程用例、20 条质控用例与 254 项逆向断言全部通过。

10.1 结论

  • 常规检验全流程 10/10 通过，状态机流转与非法操作拦截均符合预期，仪器 ASTH 回传结果准确落库并自动生成已发布报告

  • 两套质控体系（生化 10 次在控、微生物 10 次 PASS）运行正常
  • 逆向操作 254/254 断言通过：常规检验可逐级撤销至「已申请」并删除条码；微生物报告支持取消最终、删除鉴定/药敏、重新发布及撤销培养基核收；拒收/退费/作废分支正常；全部非法逆向操作均被正确拦截
  • 系统整体满足上线前的功能与数据流验证要求

10.2 建议

  • 修复启动脚本的硬编码路径问题，并统一提供单体与微服务两套启动方式，避免误用不可执行 jar
  • 微服务聚合部署前增加 Bean 命名规范检查（同名类需显式命名），建议纳入 CI 编译校验
  • 生产环境端口规划需避开常见客户端软件占用（如 8090），并在部署文档中声明
  • 取消条码前校验并处理关联报告/结果，避免删除标本后报告残留（见缺陷 #6）
  • 补充并发/性能与异常回滚场景（仪器断连、重复回传、报告撤销并发）测试
