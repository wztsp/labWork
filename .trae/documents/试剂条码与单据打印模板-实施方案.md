# 试剂条码与单据打印模板 实施方案

## Context

试剂管理目前已有打印基础设施，但**内容不可自定义**：

- [print.ts](file:///d:/traeitem/labWork/LIS-clinical-lab-solution/lis-frontend/src/utils/print.ts)：统一打印窗口（iframe 静默打印 / 新窗口预览），保留复用。
- [printConfig.ts](file:///d:/traeitem/labWork/LIS-clinical-lab-solution/lis-frontend/src/utils/printConfig.ts)：纸张尺寸、缩放、条码宽高、字号、边距、边框，**存 localStorage**，仅覆盖"排版参数"。
- [reagentPrint.ts](file:///d:/traeitem/labWork/LIS-clinical-lab-solution/lis-frontend/src/utils/reagentPrint.ts)：试剂条码标签打印/补打，**标签上显示哪些字段、字段顺序、条码值全部写死**；且打印 HTML 通过 `https://cdn.jsdelivr.net` 加载 JsBarcode，**离线部署环境直接失效**。
- 单据（申请单/采购订单/入库单/领用出库单/盘点单/报损单）**完全没有打印能力**。

目标：提供一套「打印模板」体系 —— 条码标签与 6 类单据的版式、字段、条码内容均可通过**可视化拖拽设计器**自定义，模板**后端集中存储**（多终端共用、可设默认），打印过程**零外网依赖**。

## 范围与约定

| 项 | 内容 |
| --- | --- |
| 业务类型（bizType） | `REAGENT_LABEL` 试剂条码标签、`PURCHASE_APPLY` 采购申请单、`PURCHASE_ORDER` 采购订单、`INBOUND` 入库单、`REQUISITION` 领用/出库单、`STOCK_CHECK` 盘点单、`SCRAP_DISPOSAL` 报损单 |
| 码制 | CODE128 一维码 + QR 二维码 |
| 元素类型 | 文本、字段（标签+值）、条码、二维码、横线、矩形、图片（LOGO）、明细表格 |
| 坐标单位 | mm（与现有 `buildPrintCss` 的 mm 体系一致，1mm = 3px 预览比例） |
| 纸张 | 沿用现有 `PAPER_PRESETS`（A4/A5/标签 40×30 … 100×80/自定义），模板自带宽高 |

已确认的业务口径（不重复设计）：

- 报损单 = `lis_reagent_requisition` 中 `req_type=3` 的报废单 + `lis_reagent_scrap_disposal` 处置扩展，**单号取 `reqNo`**（该表无独立单号）。
- 领用/出库单 = `req_type=1/2`，同表复用同一模板。

## 一、数据库（新增 1 张表）

文件：`lis-system/docs/database/add-reagent-print-template.sql`，并追加到 `deploy/db/init.sql`、`deploy-package/db/init.sql`（与三方卫材 DDL 同样的处理方式）。

```sql
CREATE TABLE IF NOT EXISTS lis_print_template (
    id             BIGSERIAL PRIMARY KEY,
    template_code  VARCHAR(64)  NOT NULL,
    template_name  VARCHAR(128) NOT NULL,
    biz_type       VARCHAR(32)  NOT NULL,
    paper_width    DECIMAL(6,1) NOT NULL DEFAULT 210,
    paper_height   DECIMAL(6,1) NOT NULL DEFAULT 297,
    margin         DECIMAL(5,1) NOT NULL DEFAULT 5,
    template_json  TEXT         NOT NULL,
    is_default     SMALLINT     NOT NULL DEFAULT 0,
    status         SMALLINT     NOT NULL DEFAULT 1,
    remark         VARCHAR(500),
    create_by      VARCHAR(50),
    create_time    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_by      VARCHAR(50),
    update_time    TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_lis_print_template_code ON lis_print_template (template_code);
-- 同一业务类型只允许一个默认模板
CREATE UNIQUE INDEX IF NOT EXISTS uk_lis_print_template_default
    ON lis_print_template (biz_type) WHERE is_default = 1 AND status = 1;
```

种子数据：为 7 个 bizType 各插入 1 个「默认模板」（用现有版式还原：标签沿用 reagentPrint 布局；单据用 A4 表头 + 明细表格 + 签字栏），`INSERT ... ON CONFLICT (template_code) DO NOTHING`，保证开箱即用且可重复执行。

### template_json 结构

```jsonc
{
  "version": 1,
  "canvas": { "width": 60, "height": 40, "background": "#ffffff" },
  "elements": [
    { "id": "e1", "type": "text",  "x": 2, "y": 2, "w": 56, "h": 5, "text": "试剂标签", "fontSize": 10, "bold": true, "align": "center" },
    { "id": "e2", "type": "field", "x": 2, "y": 8, "w": 56, "h": 4, "field": "reagentName", "label": "试剂", "labelWidth": 12, "fontSize": 9 },
    { "id": "e3", "type": "barcode", "x": 2, "y": 26, "w": 56, "h": 10, "symbology": "CODE128", "value": "{{barcode}}", "showText": true },
    { "id": "e4", "type": "table", "x": 10, "y": 40, "w": 190, "h": 120, "rowHeight": 7,
      "columns": [ { "field": "reagentName", "title": "试剂名称", "width": 50, "align": "left" } ] }
  ]
}
```

- `{{字段名}}` 为变量插值，条码值支持组合：`"{{reagentCode}}-{{lotNo}}"`、`"RG{{reagentId}}"`。
- 表格元素的 `columns[].field` 对应 `items` 中的键，`fieldPrefix` 固定为 `items.`。

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/page?current&size&bizType&keyword&status` | 分页 |
| GET | `/list?bizType` | 启用模板列表（打印时选模板） |
| GET | `/fields?bizType` | 字段字典（设计器左侧字段面板数据源） |

`/api/reagent/print-data`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/{bizType}/{id}` | 返回 `{ header: {...}, items: [...], extra: {...} }` |

`PrintDataService` 复用现有方法，不新写查询：

| bizType | 数据来源 |
| --- | --- |
| PURCHASE_APPLY | `ReagentPurchaseApplyService.getDetail(id)` → `ApplyDetailVO.apply` + `items` |
| PURCHASE_ORDER | `ReagentPurchaseOrderService.getDetail(id)` |
| INBOUND | `ReagentInboundService.getDetail(id)` |
| REQUISITION / SCRAP_DISPOSAL | `ReagentRequisitionService.getDetail(id)`；SCRAP 额外用 `ReagentScrapDisposalService.getByReqId(reqId)` 补处置字段 |
| STOCK_CHECK | `ReagentStockCheckService.getById(id)` + `ReagentStockCheckItemMapper.selectList(eq checkId)` |

返回的 `header` 统一扁平化（`orderNo`/`supplierName`/`totalAmount`…），金额与日期统一成字符串，避免模板渲染时格式差异；`items` 为明细数组。

### 渲染与离线要求（关键）

1. 条码/二维码**在父窗口预渲染为 SVG 字符串**，直接内联进 iframe 打印 HTML，打印页不发起任何网络请求（解决内网/离线环境现状缺陷）。
2. 打印 HTML 使用 `buildPrintCss(cfg, '.print-page')` 的 mm + `@page` 体系，与现有打印保持一致；标签模板按 `paperHeight` 分页，单据模板内容超长自动续页。
3. 所有动态值经 `escapeHtml` 处理后再拼入 HTML（遵循 [print.ts](file:///d:/traeitem/labWork/LIS-clinical-lab-solution/lis-frontend/src/utils/print.ts) 头部注释的 XSS 约定）。

## 五、风险与取舍

- **不做拖拽嵌套/多图层**：仅绝对定位 + 单层元素，满足标签与单据版式需求，避免引入重型设计器。
- **不做服务端 PDF 渲染**：打印走浏览器打印（现有 `--kiosk-printing` 可静默），避免新增 PDF 引擎与字体依赖。
- **报损单无独立单号**：沿用 `reqNo`，模板中字段名标注为「报废单号」。
- **模板 JSON 兼容**：`version` 字段预留；解析失败时回退该 bizType 默认模板，并在页面提示。
