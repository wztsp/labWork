## 二、问题详细分析与修复

### 2.1 JWT序列化器缺失问题

**问题描述**:
- 登录接口 `POST /api/auth/login` 返回500错误
- 错误信息: `Unable to find an implementation for interface io.jsonwebtoken.io.Serializer`

**根本原因**:
- Spring Boot打包时未正确保留 `META-INF/services` 目录下的SPI配置文件
- `jjwt-jackson` 包中的 `io.jsonwebtoken.io.Serializer` 实现类未被正确加载

**修复方案**:
1. 在 `lis-monolith/src/main/resources/META-INF/services/` 目录下手动创建SPI配置文件
2. 配置文件列表:
   - `io.jsonwebtoken.io.Serializer` → `io.jsonwebtoken.jackson.io.JacksonSerializer`
   - `io.jsonwebtoken.io.Deserializer` → `io.jsonwebtoken.jackson.io.JacksonDeserializer`
   - `io.jsonwebtoken.CompressionCodec` → Deflate/Gzip压缩编解码器
3. 使用无BOM的UTF-8编码保存文件

**修改文件**:
- 新增: `lis-monolith/src/main/resources/META-INF/services/io.jsonwebtoken.io.Serializer`
- 新增: `lis-monolith/src/main/resources/META-INF/services/io.jsonwebtoken.io.Deserializer`
- 新增: `lis-monolith/src/main/resources/META-INF/services/io.jsonwebtoken.CompressionCodec`

**验证结果**:
```
POST /api/auth/login (admin/123456)
→ HTTP 200, 返回token成功
```

### 2.2 系统管理模块401错误

**问题描述**:
- 用户列表、角色列表等系统管理接口返回401未经授权错误
- 即使携带了有效的Bearer Token

**根本原因**:
- `PermissionInterceptor` 权限拦截器仅从网关注入的 `X-User-Id` 请求头获取用户ID
- 直连场景下（无网关）无法获取用户身份
- Redis不可用时无降级策略

**修复方案**:
1. 在 `PermissionInterceptor` 中添加JWT Token解析降级逻辑
2. 支持从 `Authorization: Bearer <token>` 头解析用户ID
3. 添加Redis可用性检测及降级策略
4. Redis不可用时，已通过JWT认证的用户自动放行

**修改文件**:
- `lis-common/src/main/java/com/lis/common/security/PermissionInterceptor.java`
  - 新增 `resolveUserId()` 方法
  - 新增 `isRedisAvailable()` 方法
  - 修改 `preHandle()` 方法支持降级逻辑

**验证结果**:
```
GET /api/system/users?current=1&size=10 (携带Token)
→ HTTP 200, 返回3个用户记录

GET /api/system/roles?current=1&size=10 (携带Token)  
→ HTTP 200, 返回5个角色记录

GET /api/system/departments (携带Token)
→ HTTP 200, 返回科室列表
```

### 2.3 质控月报500错误

**问题描述**:
- 质控月报接口 `GET /api/qc/report/monthly` 返回500错误
- 查询 `lis_qc_record` 表时出现异常

**根本原因**:
- `lis_qc_record` 表无数据时，统计计算逻辑未正确处理空数据场景

**修复方案**:
- 代码中已包含空数据判断逻辑（`total == 0` 时返回默认值0.0）
- 接口现在可以正常返回空数据的统计结果

**验证结果**:
```
GET /api/qc/report/monthly?year=2026&month=8
→ HTTP 200
→ 返回: totalRecords=0, outOfControlRate=0.0 (空数据正常返回)
```

### 2.4 趋势分析500错误

**问题描述**:
- 趋势分析接口 `GET /api/stats/trend` 返回500错误
- 查询 `lis_result` 表关联 `lis_sample` 时出现异常

**根本原因**:
- 之前的代码版本可能使用了不存在的字段 `signoff_time`
- 当前代码已修正为使用 `lis_result.test_time` 字段

**修复方案**:
- 确认当前代码使用正确的字段进行查询
- 接口现在可以正常返回趋势分析数据

**验证结果**:
```
GET /api/stats/trend?patientId=1&testItemId=1
→ HTTP 200
→ 返回: 患者历史检测结果列表

GET /api/stats/trend/positive-rate?startDate=2026-08-01&endDate=2026-08-31
→ HTTP 200
→ 返回: 阳性率统计数据
```
