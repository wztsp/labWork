# LIS 核心页面设计审查报告

> 审查范围：标本采集、标本送检、标本签收、技师工作站、报告查询
> 审查维度：信息架构、交互效率、布局合理性、异常处理、可访问性、响应式
> 评级标准：A 优秀 / B 合格 / C 需改进 / D 有风险

---

## 一、页面全景与流转关系

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────────┐     ┌──────────┐
│ 标本采集   │────→│ 标本送检   │────→│ 标本签收   │────→│ 技师工作站    │────→│ 报告查询  │
│ Collect   │     │ Transport │     │ Receive   │     │ Workstation  │     │ Query    │
└──────────┘     └──────────┘     └──────────┘     └──────────────┘     └──────────┘
  护士/采血岗      物流/运送员        检验科收样岗       检验技师            临床医生/患者
  移动端优先        移动端优先          PC 工作台          PC 工作台            PC/移动端
```

**流转核心问题**：这五个页面分属不同角色，页面间通过标本条码串联。设计上必须保证条码在每个环节都能被快速扫描识别，且状态流转对上下游可见。

---

## 二、逐页审查

### 2.1 标本采集页面 (Specimen Collection)

**使用场景**：护士/采血人员根据检验申请，采集患者标本，打印/粘贴条码。
**使用设备**：移动平板为主，PC 为辅。

#### 当前设计结构

```
┌─────────────────────────────────────────────────────┐
│  [申请列表表格]                                        │
│  患者 | 申请项目 | 标本类型 | 容器 | 状态 | 操作       │
├─────────────────────────────────────────────────────┤
│  [点击操作 → 弹窗采集确认]                              │
│  患者信息 → 选择容器 → 打印条码 → 确认采集               │
└─────────────────────────────────────────────────────┘
```

#### 问题与风险

| 序号 | 问题 | 严重度 | 说明 |
|------|------|--------|------|
| 1 | 采集确认依赖弹窗，每次采集需 3-4 次点击 | 高 | 高峰期每小时上百次操作，弹窗交互效率低 |
| 2 | 患者身份核对缺少扫码环节 | 高 | 仅靠表格视觉核对姓名，存在采错人风险 |
| 3 | 容器类型选择需手动下拉 | 中 | 应根据申请项目自动匹配推荐容器 |
| 4 | 采集时间未强制记录到分钟 | 中 | 影响 TAT 统计准确性 |
| 5 | 移动端布局未做平板优化 | 中 | 表格在 10 寸平板上列过多，横向滚动频繁 |
| 6 | 采集失败/拒采缺少快捷操作 | 中 | 患者拒绝采血、血管难找等场景无标准处理流程 |

#### 改进建议

**1. 采用"扫码驱动的线性流程"替代表格弹窗**

```
┌──────────────────────────────────────────────────────┐
│                                                      │
│  ┌────────────────────────────────────────────┐      │
│  │  [扫码区] 扫描申请单/腕带条码               │      │
│  │  ─────────────────────────────────────────  │      │
│  │  患者：张三  男 35岁  门诊号：M20260815001  │      │
│  │  ─────────────────────────────────────────  │      │
│  │  待采项目：                                │      │
│  │  [血常规]   紫色EDTA管 ×1  [打印条码]       │      │
│  │  [生化全套] 红色促凝管 ×1 [打印条码]        │      │
│  │  [凝血四项] 蓝色枸橼酸钠管 ×1 [打印条码]    │      │
│  │  ─────────────────────────────────────────  │      │
│  │  推荐容器已自动匹配，可手动调整              │      │
│  │  ─────────────────────────────────────────  │      │
│  │  [确认采集]  [采集失败]  [跳过]             │      │
│  └────────────────────────────────────────────┘      │
│                                                      │
│  最近采集记录 (可撤销 5 分钟内操作)                     │
│  张三 血常规 10:23  [撤销]                            │
│  李四 尿常规 10:20  [撤销]                            │
└──────────────────────────────────────────────────────┘
```

**2. 强制双向扫码核对**：扫申请单 + 扫腕带，系统校验一致后才允许采集，防止采错人。

**3. 容器自动匹配**：根据 `lis_test_item.specimen_type` 和 `container_type` 字段自动推荐，默认选中，允许手动改。

**4. 采集失败快捷操作**：提供标准化原因下拉（血管难找/患者拒绝/标本量不足/其他），一键记录，自动通知临床。

**5. 移动端优化**：采集页面以卡片式纵向布局为主，禁用横向表格；条码打印通过蓝牙连接便携打印机。

#### 评级：C（需改进）

核心瓶颈是交互效率。采血高峰期每分钟可能处理 2-3 个患者，弹窗模式无法满足。必须改为扫码驱动的线性流程，减少点击次数到 2 次以内（扫码 + 确认）。

### 2.2 标本送检页面 (Specimen Transport)

**使用场景**：运送员将采集好的标本从采集点送往检验科，记录运送信息。
**使用设备**：手机/移动终端为主。

#### 当前设计结构

```
┌─────────────────────────────────────────────────────┐
│  [送检单列表]                                         │
│  送检单号 | 来源科室 | 标本数 | 状态 | 操作            │
├─────────────────────────────────────────────────────┤
│  [新建送检 → 选择标本 → 确认送检]                      │
└─────────────────────────────────────────────────────┘
```

#### 问题与风险

| 序号 | 问题 | 严重度 | 说明 |
|------|------|--------|------|
| 1 | 逐个选择标本效率极低 | 高 | 一个送检袋可能有 20-30 个标本，逐个勾选不可接受 |
| 2 | 缺少批量扫码功能 | 高 | 运送员需要快速扫袋内所有标本 |
| 3 | 送检途中标本状态不可见 | 中 | 标本离开采集点后到签收前存在"盲区" |
| 4 | 缺少运送时长统计 | 中 | 无法监控运送 TAT，标本延误难追责 |
| 5 | 标本遗漏/丢失无预警 | 高 | 送检数量与签收数量不一致时无提醒 |
| 6 | 移动端无离线模式 | 中 | 地下室/电梯间网络差，扫码数据可能丢失 |

#### 改进建议

**1. 批量扫码打包模式**

```
┌──────────────────────────────────────────────────────┐
│  标本送检                                              │
│                                                      │
│  ┌────────────────────────────────────────────┐      │
│  │  来源科室：[扫码自动识别 / 下拉选择]         │      │
│  │  目的地：  检验科 (默认)                     │      │
│  │  ─────────────────────────────────────────  │      │
│  │  📷 扫描标本条码 (连续扫描模式)              │      │
│  │  ─────────────────────────────────────────  │      │
│  │  已扫描标本 (12)                           │      │
│  │  ┌──────────────────────────────────────┐  │      │
│  │  │ 1. 张三 血常规     10:25  ✅         │  │      │
│  │  │ 2. 李四 尿常规     10:26  ✅         │  │      │
│  │  │ 3. 王五 生化全套   10:27  ✅         │  │      │
│  │  │ ...                                  │  │      │
│  │  │ 重复扫描自动忽略                      │  │      │
│  │  └──────────────────────────────────────┘  │      │
│  │  ─────────────────────────────────────────  │      │
│  │  [确认送检 (12管)]   [清除]                │      │
│  └────────────────────────────────────────────┘      │
│                                                      │
│  送检中任务 (1)                                       │
│  送检单 #TF20260815001  12管  10:30出发  [查看详情]   │
└──────────────────────────────────────────────────────┘
```

**2. 离线缓存机制**：扫码数据先存本地 SQLite/IndexedDB，网络恢复后自动同步，防止数据丢失。

**3. 运送交接确认**：送检出发时扫码打包，到达检验科时签收人扫码确认，形成完整的运送链路。

**4. 标本数量校验**：送检时记录标本数，签收时自动比对，不一致时高亮提示差异。

**5. 运送 TAT 监控**：从采集到签收的时间分段统计，超时自动预警。

#### 评级：C（需改进）

核心问题是缺少批量扫码。移动端必须支持连续扫码模式，扫一次记一次，重复自动忽略，最后一键确认。这是运送场景的刚需。

### 2.3 标本签收页面 (Specimen Receipt)

**使用场景**：检验科收样人员扫码签收标本，核对标本信息，拒收不合格标本。
**使用设备**：PC 工作台 + 条码扫描枪。

#### 当前设计结构

```
┌─────────────────────────────────────────────────────┐
│  [签收列表表格]                                       │
│  条码 | 患者 | 项目 | 标本类型 | 状态 | 签收时间 | 操作  │
├─────────────────────────────────────────────────────┤
│  [扫码 → 自动签收 / 点击操作 → 弹窗确认]               │
└─────────────────────────────────────────────────────┘
```

#### 问题与风险

| 序号 | 问题 | 严重度 | 说明 |
|------|------|--------|------|
| 1 | 扫码签收后无视觉/听觉反馈 | 高 | 扫码枪连续扫，操作员不知道哪个成功哪个失败 |
| 2 | 标本不合格拒收流程繁琐 | 高 | 溶血/量不足/容器错误等常见问题需多步操作 |
| 3 | 签收后标本分配仪器需切换页面 | 中 | 签收和分配应是连续动作，不应跨页面 |
| 4 | 急诊标本无视觉优先级 | 高 | 急诊与常规混在一起，容易遗漏急诊 |
| 5 | 批量签收无数量校验 | 中 | 无法确认是否全部签收 |
| 6 | 签收时间精度不够 | 中 | 精确到分钟，影响 TAT |
| 7 | 重复签收无防护 | 中 | 同一条码扫两次会重复签收 |

#### 改进建议

**1. 扫码签收即时反馈系统**

```
┌──────────────────────────────────────────────────────┐
│  标本签收                                              │
│                                                      │
│  ┌──────────────┐  ┌──────────────────────────┐      │
│  │ 今日统计      │  │  扫码签收区              │      │
│  │              │  │  ┌────────────────────┐  │      │
│  │ 已签收: 342  │  │  │  [条码输入框]       │  │      │
│  │ 待签收:  18  │  │  │  扫码即签收 ↓       │  │      │
│  │ 已拒收:   3  │  │  └────────────────────┘  │      │
│  │ 急诊待检: 5  │  │                          │      │
│  └──────────────┘  │  最近签收 (滚动列表)     │      │
│                    │  ┌────────────────────┐  │      │
│  ┌──────────────┐  │  │ ✅ 张三 血常规 10:25│  │      │
│  │ ⚠️ 急诊优先   │  │  │ ✅ 李四 尿常规 10:26│  │      │
│  │ 王五 血培养   │  │  │ ❌ 赵六 溶血拒收   │  │      │
│  │ 急诊 已30min  │  │  │ ✅ 钱七 生化   10:28│  │      │
│  │ [立即处理]   │  │  │                    │  │      │
│  └──────────────┘  │  └────────────────────┘  │      │
│                    │  [批量拒收]  [任务分配]   │      │
│                    └──────────────────────────┘      │
└──────────────────────────────────────────────────────┘
```

**2. 多通道反馈**：
- 视觉：成功绿色闪动 + 失败红色高亮
- 听觉：成功"滴"声 + 失败"嘟嘟"警示音
- 触觉（移动端）：成功轻震动 + 失败长震动

**3. 拒收快捷操作**：扫到不合格标本时，弹出拒收原因快捷面板（溶血/量不足/容器错误/标本凝固/标签错误/其他），一键记录并通知采集点。

**4. 急诊优先看板**：页面侧栏固定急诊标本列表，超过 30 分钟未处理变红闪烁，强制视觉提醒。

**5. 防重复签收**：已签收条码再次扫描时，提示"已签收"并显示签收人和时间，不重复操作。

**6. 签收即分配**：签收后自动根据项目匹配仪器（基于 `lis_instrument_item_map`），允许手动调整，避免二次操作。

#### 评级：C（需改进）

签收是检验科的高频操作，日均 5000 标本意味着每分钟 10+ 次扫码。没有即时反馈的扫码签收在生产环境中会造成大量误操作。多通道反馈是必须的。

### 2.4 技师工作站页面 (Technician Workstation)

**使用场景**：检验技师查看待检标本、录入/查看结果、审核报告、处理危急值。
**使用设备**：PC 工作台（双屏更佳）。

这是 LIS 系统最核心、使用频率最高的页面，也是设计复杂度最高的页面。

#### 当前设计结构

```
┌─────────────────────────────────────────────────────┐
│  [左侧: 标本列表表格]  │  [右侧: 结果录入/详情]       │
│  条码|患者|项目|状态   │  检验结果表格                 │
│                       │  项目 | 结果 | 参考 | 异常    │
│                       │  录入 / 保存 / 审核           │
└─────────────────────────────────────────────────────┘
```

#### 问题与风险

| 序号 | 问题 | 严重度 | 说明 |
|------|------|--------|------|
| 1 | 左右分栏比例固定，不可调整 | 高 | 标本多时列表太窄看不全，结果多时右侧太窄 |
| 2 | 结果录入无键盘快捷键支持 | 高 | 技师录入结果全靠鼠标点击，效率极低 |
| 3 | 危急值处理未集成到工作站 | 高 | 危急值需跳转到单独页面处理，打断工作流 |
| 4 | 历史结果对比缺少可视化 | 中 | 仅文字显示历史值，趋势变化不直观 |
| 5 | 仪器自动采集结果与手工录入混淆 | 中 | 无法快速区分哪些是仪器传的、哪些是手输的 |
| 6 | 批量审核缺少风险提示 | 高 | 一键批量审核时未提示异常结果 |
| 7 | 标本状态过滤不够灵活 | 中 | 只能按单一状态过滤，无法多条件组合 |
| 8 | 结果修改无留痕提示 | 高 | 修改已审核结果时不显示修改历史 |
| 9 | 工作站无个性化配置 | 中 | 每个技师关注的项目和列不同，无法自定义 |

#### 改进建议

**1. 三栏自适应布局 + 可拖拽分栏**

```
┌────────┬──────────────────────────┬────────────────┐
│ 标本列表 │  结果录入区               │  辅助信息区     │
│ (可折叠) │  (主工作区)               │  (可折叠)      │
│        │                          │                │
│ 筛选:   │  患者：张三 男 35岁        │  历史结果      │
│ [待检▼] │  条码：S20260815001       │  ┌──────────┐ │
│ [急诊▲] │  仪器：Sysmex XN-9000     │  │ WBC 趋势图│ │
│        │  ─────────────────────    │  │ (折线图) │ │
│ 列表:   │  项目   结果   参考   异常 │  └──────────┘ │
│ ┌────┐ │  WBC    6.5   4-10   N   │                │
│ │张三 │ │  RBC    4.5   3.5-5.5 N   │  临床诊断:    │
│ │待检 │ │  HGB    135   120-160 N  │  发热待查      │
│ ├────┤ │  PLT    220   100-300 N  │                │
│ │李四 │ │  ─────────────────────    │  采集信息:    │
│ │危急 │ │  ⚠️ GLU 18.5 危急值!      │  10:25 采血   │
│ ├────┤ │     [确认危急值] [复核]    │  10:40 签收   │
│ │王五 │ │  ─────────────────────    │                │
│ │审核中│ │  [保存草稿] [提交审核]    │  试剂批号:    │
│ └────┘ │  [批量审核] [打印报告]    │  LOT20260801  │
│        │                          │                │
│ ←拖拽→ │  ←───── 拖拽 ─────→       │  ←拖拽→        │
└────────┴──────────────────────────┴────────────────┘
```

**2. 键盘快捷键体系**

| 快捷键 | 功能 |
|--------|------|
| `F2` | 聚焦到下一个未录入结果项 |
| `F3` | 保存当前结果 |
| `F4` | 提交审核 |
| `F8` | 标记危急值已确认 |
| `Ctrl+S` | 保存草稿 |
| `Ctrl+Enter` | 快速审核（仅无异常时生效） |
| `↑` `↓` | 在结果项之间切换 |
| `Tab` | 跳到下一个标本 |
| `Esc` | 取消当前操作 |

**3. 危急值内嵌处理**：检测到危急值时，在结果区域就地展开危急值确认面板（通知临床 + 记录确认人和时间），不跳转页面。

**4. 结果来源标记**：每行结果用图标区分来源（仪器自动 / 手工录入 / 修改过），悬停显示详细来源信息。

```
WBC  6.5  4-10  N   🔧(仪器自动)
GLU  18.5 危急      ✏️(手工录入)  ⚠️
ALT  45   0-40  H   ✏️(已修改 2次)
```

**5. 历史趋势可视化**：右侧辅助区用 ECharts 迷你折线图展示最近 5 次结果趋势，异常值标红。

**6. 批量审核安全门**：批量审核前弹出确认面板，列出所有异常项和危急值，要求二次确认。

**7. 个性化配置**：支持保存列宽、筛选条件、常用项目排序为个人预设，登录后自动恢复。

**8. 结果修改留痕**：修改已审核结果时，结果单元格显示修改标记（黄色背景 + 角标），点击查看修改历史。

#### 评级：D（有风险）

技师工作站是整个 LIS 的核心生产力工具。当前设计在交互效率上有严重缺陷：无快捷键、无危急值内嵌处理、无历史趋势可视化。对于日均 5000 标本的实验室，这些缺陷会直接导致效率下降和安全隐患。建议作为最高优先级重新设计。

### 2.5 报告查询页面 (Report Query)

**使用场景**：临床医生/患者查询检验报告，查看结果，对比历史。
**使用设备**：PC 为主，移动端为辅。

#### 当前设计结构

```
┌─────────────────────────────────────────────────────┐
│  [查询条件区]                                         │
│  患者/条码/日期范围/项目                              │
├─────────────────────────────────────────────────────┤
│  [报告列表表格]                                       │
│  报告号|患者|项目|日期|状态|操作                       │
├─────────────────────────────────────────────────────┤
│  [点击查看 → 报告详情弹窗/新页面]                      │
└─────────────────────────────────────────────────────┘
```

#### 问题与风险

| 序号 | 问题 | 严重度 | 说明 |
|------|------|--------|------|
| 1 | 查询条件过多，高频查询场景不明确 | 中 | 医生最常按患者查，但患者查询条件不够突出 |
| 2 | 报告详情用弹窗，信息密集时空间不足 | 高 | 微生物报告、生化大套餐等结果项多，弹窗装不下 |
| 3 | 历史结果对比需手动选择 | 中 | 应自动展示同项目历史趋势 |
| 4 | 报告状态对临床医生不透明 | 中 | "审核中"报告医生看不到，不知何时出结果 |
| 5 | 异常结果视觉标记不够醒目 | 中 | 仅靠字母 H/L 标记，颜色不突出 |
| 6 | 报告打印格式在不同浏览器不一致 | 中 | CSS 打印兼容性问题 |
| 7 | 移动端报告查看未优化 | 中 | 表格在手机上横向滚动，可读性差 |
| 8 | 危急值报告无特殊标识 | 高 | 临床医生无法快速识别危急值报告 |

#### 改进建议

**1. 分角色查询入口**

```
┌──────────────────────────────────────────────────────┐
│  报告查询                                              │
│                                                      │
│  [按患者查]  [按条码查]  [按日期查]  [按科室查]        │
│  ──────────────────────────────────────────────      │
│                                                      │
│  📌 按患者查 (最常用)                                  │
│  ┌────────────────────────────────────────────┐      │
│  │ 姓名/住院号/门诊号: [____________] [搜索]    │      │
│  │ 日期范围: [最近7天 ▼]                       │      │
│  └────────────────────────────────────────────┘      │
│                                                      │
│  查询结果                                             │
│  ┌────────────────────────────────────────────┐      │
│  │ 张三  男 35岁  门诊号 M20260815001          │      │
│  │ ┌────────────────────────────────────────┐ │      │
│  │ │ 📄 血常规     08-15 10:30  已发布       │ │      │
│  │ │    WBC 6.5  RBC 4.5  HGB 135  PLT 220  │ │      │
│  │ │    [查看详情]  [打印]  [历史对比]       │ │      │
│  │ ├────────────────────────────────────────┤ │      │
│  │ │ ⚠️ 生化全套   08-15 11:00  已发布       │ │      │
│  │ │    GLU 18.5↑ ALT 45↑  AST 38           │ │      │
│  │ │    🔴 含危急值: GLU                     │ │      │
│  │ │    [查看详情]  [打印]  [历史对比]       │ │      │
│  │ ├────────────────────────────────────────┤ │      │
│  │ │ 🕐 凝血四项   08-15 11:30  审核中       │ │      │
│  │ │    预计 12:00 发布                      │ │      │
│  │ └────────────────────────────────────────┘ │      │
│  └────────────────────────────────────────────┘      │
└──────────────────────────────────────────────────────┘
```

**2. 报告详情用独立页面而非弹窗**：详情页面空间充足，支持完整结果展示 + 历史趋势图 + 打印预览。

**3. 异常结果多级视觉标记**

| 标记级别 | 视觉表现 | 含义 |
|---------|---------|------|
| 正常 | 无标记 / 绿色 | 结果在参考范围内 |
| 偏高 | 黄色背景 + ↑ 箭头 | 结果高于参考范围 |
| 偏低 | 黄色背景 + ↓ 箭头 | 结果低于参考范围 |
| 危急值 | 红色背景 + 闪烁 + 警示图标 | 结果达到危急值 |
| 修改过 | 黄色角标 | 结果被修改过 |

**4. 自动历史对比**：报告详情页自动展示同项目最近 5 次结果的趋势折线图，无需手动选择。

**5. 报告状态透明化**：临床医生可见三种状态——已发布（可查看完整报告）、审核中（显示项目列表 + 预计发布时间）、未出（显示检测进度）。

**6. 打印格式标准化**：使用 `@media print` CSS 严格控制打印布局，统一 A4 格式，关键信息（患者信息、结果、审核人签名、报告日期）位置固定。

**7. 移动端适配**：报告在手机上以卡片式展示，每个检验项目一张卡片，结果横向滚动表格改为纵向堆叠。

**8. 危急值报告特殊标识**：含危急值的报告在列表中用红色边框 + 警示图标标记，详情页顶部显示危急值提示条。

#### 评级：B（合格，需优化）

基本查询功能可用，但在临床体验上有较大提升空间。核心改进是让异常结果和危急值在视觉上更突出，以及自动展示历史趋势，减少医生的操作步骤。

## 三、跨页面共性问题

### 3.1 条码扫描体验不一致

| 页面 | 扫码方式 | 反馈 | 问题 |
|------|---------|------|------|
| 采集 | 手动输入 | 无 | 应支持扫码枪/摄像头 |
| 送检 | 手动选择 | 无 | 应支持连续扫码 |
| 签收 | 扫码但无反馈 | 无 | 需多通道反馈 |
| 工作站 | 无扫码 | - | 应支持扫码定位标本 |
| 查询 | 无扫码 | - | 应支持扫码查报告 |

**建议**：统一封装条码扫描组件，支持扫码枪（USB HID 模式）和摄像头扫描（移动端），所有页面复用。扫码后有统一的视觉 + 听觉反馈。

### 3.2 标本状态流转可见性

当前各页面独立展示标本状态，缺乏跨环节的全链路视图。

**建议**：在每个页面的标本详情中，增加标本生命周期时间轴：

```
采集 10:25 ──→ 送检 10:30 ──→ 签收 10:45 ──→ 检测 10:50 ──→ 报告 11:15
  ✅             ✅              ✅             ✅             ✅
```

超时环节标红，帮助各环节人员快速定位延误点。

### 3.3 急诊标本优先级贯穿

当前仅签收页面有急诊标识，其他页面缺失。

**建议**：全页面统一急诊标识——红色标签 + 置顶排序 + 超时预警。任何环节的列表中，急诊标本自动排到最前面。

### 3.4 响应式断点缺失

当前设计未明确响应式断点。

**建议**：

| 设备 | 断点 | 布局策略 |
|------|------|---------|
| 手机 | < 768px | 单列卡片式，表格转纵向堆叠 |
| 平板 | 768px - 1024px | 双栏，侧栏可折叠 |
| PC | 1024px - 1440px | 三栏布局 |
| 大屏/双屏 | > 1440px | 三栏 + 辅助信息展开 |

### 3.5 颜色规范未统一

各页面异常标记、状态颜色不统一。

**建议**：建立全局颜色语义规范：

| 语义 | 颜色 | 场景 |
|------|------|------|
| 正常/成功 | 绿色 `#52C41A` | 正常结果、成功操作 |
| 警告/偏高 | 橙色 `#FAAD14` | 异常结果、近效期 |
| 危急/错误 | 红色 `#F5222D` | 危急值、拒收、超时 |
| 信息/进行中 | 蓝色 `#1890FF` | 审核中、检测中 |
| 灰色/已完成 | 灰色 `#8C8C8C` | 已发布、已签收 |

## 五、总结

| 页面 | 评级 | 核心瓶颈 |
|------|------|---------|
| 标本采集 | C | 弹窗交互效率低，缺少扫码核对 |
| 标本送检 | C | 缺少批量连续扫码 |
| 标本签收 | C | 扫码无即时反馈，急诊无优先 |
| 技师工作站 | D | 无快捷键，危急值未内嵌，布局不可调 |
| 报告查询 | B | 异常标记不醒目，历史趋势需手动 |

**最高优先级建议**：技师工作站和标本签收页面应立即重新设计。这两个页面是检验科日常使用频率最高的页面，直接关系到日均 5000 标本的处理效率和患者安全。

**设计原则总结**：
1. 高频操作零跳转——能在一个页面完成的绝不分页
2. 扫码驱动而非鼠标驱动——减少点击次数
3. 即时反馈——每次操作都有明确的视觉/听觉确认
4. 异常前置——危急值、急诊、超时等异常信息必须最先被看到
5. 键盘优先——技师工作站的双手应始终在键盘上，而非键盘鼠标来回切换
