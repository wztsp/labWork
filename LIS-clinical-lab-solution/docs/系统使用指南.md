# LIS临床实验室信息管理系统 - 系统使用指南

## 一、系统概述

本系统是基于Spring Cloud微服务架构的临床实验室信息管理系统(LIS)，采用前后端分离架构：

- **后端**: Spring Boot 3.2 + Spring Cloud Alibaba + PostgreSQL 15 + Redis 7
- **前端**: Vue 3 + TypeScript + Vite + Element Plus
- **服务治理**: Nacos 2.x（服务注册发现、配置中心）
- **网关**: Spring Cloud Gateway（统一入口、JWT认证）

### 核心功能模块

| 模块 | 端口 | 功能说明 |
|------|------|----------|
| lis-auth | 8090 | 认证授权服务（JWT登录） |
| lis-service-system | 8087 | 系统管理（用户、角色、权限） |
| lis-service-base | 8085 | 基础数据（检验项目、参考范围、仪器） |
| lis-service-sample | 8081 | 标本管理（标本采集、接收、流转） |
| lis-service-report | 8091 | 报告管理（报告生成、审核、发布） |
| lis-service-qc | 8092 | 质量控制（室内质控、Westgard规则） |
| lis-service-instrument | 8093 | 仪器通讯（ASTM/HL7协议解析） |
| lis-service-instrument-mgmt | 8091 | 仪器管理（维护计划、保养记录） |
| lis-service-reagent | 8092 | 试剂管理（库存、效期、出入库） |
| lis-service-micro | 8093 | 微生物报告（血培养、药敏试验） |
| lis-service-hr | 8094 | 人力资源管理（人员、培训、排班） |
| lis-service-stats | 8088 | 统计分析（工作量、危急值统计） |
| lis-service-integration | 8089 | 第三方集成（HIS对接、HL7/FHIR） |
| lis-gateway | 8080 | API网关（统一入口） |

## 三、服务启动方法

### 3.1 一键启动所有服务（推荐）

系统已提供一键启动脚本，会自动启动所有后端服务：

```powershell
# 进入项目目录
cd d:\traeitem\labWork

# 执行启动脚本（已优化连接池配置）
powershell -ExecutionPolicy Bypass -File restart-all-services.ps1
```

**启动过程**：
1. 自动停止所有旧的Java进程（保留Nacos）
2. 按依赖顺序启动14个微服务
3. 每个服务使用HikariCP连接池大小为3（避免超出PostgreSQL 100连接限制）
4. 等待30秒让服务完成注册

### 3.2 手动启动（可选）

如果需要单独启动某个服务：

```powershell
# 设置环境变量
$env:DB_PASSWORD = "lis_dev_2026"

# 启动认证服务
java -jar -Dspring.datasource.hikari.maximum-pool-size=3 "d:\traeitem\labWork\LIS-clinical-lab-solution\lis-system\lis-auth\target\lis-auth-1.0.0.jar"

# 启动网关服务
java -jar -Dspring.datasource.hikari.maximum-pool-size=3 "d:\traeitem\labWork\LIS-clinical-lab-solution\lis-system\lis-gateway\target\lis-gateway-1.0.0.jar"

# 启动其他服务...
```

**启动顺序建议**：
1. Nacos（已通过脚本启动，端口8848）
2. 认证服务（lis-auth，端口8090）
3. 系统服务（lis-service-system，端口8087）
4. 其他业务服务
5. 网关（lis-gateway，端口8080）

### 3.3 启动基础设施服务

如果基础设施（PostgreSQL、Redis、Nacos）未启动：

```powershell
# 启动PostgreSQL（Windows服务）
net start postgresql-x64-13

# 启动Redis（假设已安装为服务）
net start Redis

# 启动Nacos（独立模式）
cd d:\traeitem\labWork\infra\nacos\nacos
startup.cmd -m standalone
```

## 七、常见问题排查

### 7.1 服务启动失败

**症状**：端口未监听，服务无法访问

**排查步骤**：
1. 检查PostgreSQL是否启动：`netstat -ano | findstr :5432`
2. 检查Redis是否启动：`netstat -ano | findstr :6379`
3. 检查Nacos是否启动：`netstat -ano | findstr :8848`
4. 查看服务日志：检查控制台输出的错误信息

### 7.2 登录失败

**症状**：提示"用户不存在或密码错误"

**解决方案**：
```powershell
# 重置admin用户密码
$env:PGPASSWORD = "lis_dev_2026"
& "D:\Program Files\PostgreSQL\13\bin\psql.exe" -U lis_user -d lis_db -c "UPDATE sys_user SET password = '\$2a\$10\$N.zmdr9k7uOCQb3ZQMKT.eX7pI8sYCZK4lCvH9Jl5N0.G9J5V8Gq6' WHERE username = 'admin';"
```

### 7.3 PostgreSQL连接超限

**症状**：错误提示"致命错误: 已保留的连接位置为执行非复制请求的超级用户预留"

**原因**：所有服务的HikariCP连接池总和超过PostgreSQL的max_connections限制（默认100）

**解决方案**：
```powershell
# 使用优化后的启动脚本（每个服务连接池大小=3）
powershell -ExecutionPolicy Bypass -File restart-all-services.ps1
```

### 7.4 前端无法连接后端

**症状**：前端界面打开但无法加载数据，控制台报跨域错误

**检查项**：
1. 确认网关服务已启动（端口8080）
2. 检查前端配置的API地址是否正确（应指向网关）
3. 检查浏览器开发者工具Network面板的请求响应

**前端配置文件**：`lis-frontend/.env.development`
```
VITE_API_BASE_URL=http://localhost:8080
```
