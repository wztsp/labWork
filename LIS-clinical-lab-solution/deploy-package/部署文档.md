## 0. 目录一览

解压 `deploy-package.zip` 后目录结构如下：

```
deploy-package/
├── backend/
│   ├── lis-monolith-fresh.jar      # 后端一体化 JAR（内嵌前端 dist）
│   └── application.yml             # 应用配置（端口 / 数据库 / Redis / MQ / TCP 仪器通讯）
├── db/
│   ├── init.sql                    # 数据库建表 Schema
│   └── seed_30_technician.sql      # 示例数据（可选，首次导入）
├── init-db.ps1                     # Windows 数据库初始化脚本
├── start.bat                       # Windows 启动脚本
├── start.sh                        # Linux 启动脚本
├── 操作文档.md                      # 用户操作手册
└── 部署文档.md                      # 本文件
```

## 1. 环境要求

### 1.1 硬件（最低 / 推荐）

| 维度 | 最低（演示 / 小型实验室） | 推荐（生产环境，≥50 用户） |
| --- | --- | --- |
| CPU | 4 核 | 8 核 16 线程 或更高 |
| 内存 | 8 GB | 16 GB 或更高 |
| 磁盘 | 100 GB SSD | 500 GB SSD（报告 PDF / 备份） |
| 操作系统 | Windows Server 2016+ 或 CentOS 7+ / Ubuntu 20.04+ | Windows Server 2019+ 或 RHEL 8+ / Ubuntu 22.04+ |

### 1.2 软件

| 组件 | 版本要求 | 必选/可选 | 说明 |
| --- | --- | --- | --- |
| JDK | 17（推荐 17.0.7+） | 必选 | OpenJDK / Oracle JDK / Eclipse Temurin 均可；需配置 `PATH` |
| PostgreSQL | **14 或更高**（推荐 14.8+ / 15.x / 16.x） | 必选 | 主数据库，需开启 `UTF8` 编码 |
| Redis | 6+ | 可选 | 未配置可用但不启动时部分缓存功能降级；默认 `localhost:6379 db=3` |
| RabbitMQ | 3.11+ | 可选 | 用于危急值、报告发布等异步消息；未安装时 `auto-startup:false`，不影响核心业务 |
| 浏览器 | Chrome 108+ / Edge 108+ / Firefox 110+ / Safari 16+ | 客户端必选 | 不支持 IE |

> ⚠️ **数据库字符集硬性要求**：JDBC 连接串必须带 `characterEncoding=utf8`（本部署包已配置），防止中文乱码。

## 2. 首次部署（Step-by-Step）

### 2.1 解压部署包

将 `deploy-package.zip` 解压到 **无空格、无中文** 的路径，例如：
- Windows：`D:\lis\deploy-package\`
- Linux：`/opt/lis/deploy-package/`

### 2.2 安装前置软件

| 平台 | 命令 / 步骤 |
| --- | --- |
| Windows | 依次安装 JDK 17 → PostgreSQL 14+（勾选 Command Line Tools / pgAdmin）。<br>安装完成后在 PowerShell 执行：`java -version` 与 `psql --version` 均能输出版本即成功。 |
| Linux (Ubuntu 22.04) | `sudo apt install -y openjdk-17-jdk postgresql postgresql-contrib redis-server` |
| Linux (CentOS 8 / RHEL 8) | `sudo dnf install -y java-17-openjdk-devel postgresql-server postgresql-contrib redis` |

### 2.3 初始化 PostgreSQL 数据库

**方式 A：Windows 一键脚本（推荐）**
```powershell
# 以管理员身份打开 PowerShell，进入部署包目录
cd D:\lis\deploy-package
powershell -ExecutionPolicy Bypass -File .\init-db.ps1
```
脚本会**交互式**询问以下参数（回车可使用默认值）：

| 提示 | 默认值 | 说明 |
| --- | --- | --- |
| PostgreSQL 主机 | `localhost` | 数据库所在服务器 IP |
| PostgreSQL 端口 | `5432` | 监听端口 |
| PostgreSQL 管理员用户名 | `postgres` | 超级管理员，用于创建库/用户 |
| PostgreSQL 管理员密码 | — | 安装时设置的密码，不会明文显示 |
| 数据库名 | `lis_db` | 保持默认即可 |
| 应用用户名 | `lis_user` | LIS 业务账号 |
| 应用用户密码 | `lis_dev_2026` | 生产环境请改为强密码 |

脚本执行完成后会显示：
```
完成! 现在可以运行 start.bat 启动服务
```

**方式 B：Linux 手工命令（或自定义）**
```bash
# 1. 用 postgres 超级管理员创建用户与库
sudo -u postgres psql -c "CREATE USER lis_user WITH PASSWORD 'lis_dev_2026';"
sudo -u postgres psql -c "CREATE DATABASE lis_db OWNER lis_user ENCODING 'UTF8';"

# 2. 导入 Schema（部署包 db/ 目录下）
cd /opt/lis/deploy-package
PGPASSWORD='你的postgres密码' psql -h localhost -U postgres -d lis_db -f db/init.sql
# 3. 导入示例数据（可选）
PGPASSWORD='你的postgres密码' psql -h localhost -U postgres -d lis_db -f db/seed_30_technician.sql
```

### 2.4 确认或修改配置文件 `backend/application.yml`

关键参数说明（无特殊需求保持默认即可）：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `server.port` | `8080` | 服务端口，**前后端共用** |
| `spring.datasource.url` | `jdbc:postgresql://localhost:5432/lis_db?characterEncoding=utf8` | ✅ UTF-8 不可省略 |
| `spring.datasource.username` | `lis_user` | 与上一步创建的应用用户一致 |
| `spring.datasource.password` | `${DB_PASSWORD:lis_dev_2026}` | 可用环境变量 `DB_PASSWORD` 覆盖；冒号后为默认值 |
| `spring.redis.*` | `localhost:6379 db=3` | 无 Redis 可忽略，不影响启动 |
| `spring.rabbitmq.*` | `localhost:5672 /lis` | `auto-startup:false`，无 MQ 不阻断启动 |
| `tcp.server.port` | `9100` | 仪器 TCP 通讯端口（ASTM / 自定义） |
| `report.pdf.storage-path` | `/data/lis/pdf` | PDF 报告存储目录（Windows 会自动适配） |
| `spring.sql.init.mode` | `never` | ✅ **永远不要改**：数据初始化脚本应本地手动执行，不在启动时自动跑 |

**生产环境密码推荐写法（避免明文写在 YAML）：**
- Windows：在系统环境变量中新建 `DB_PASSWORD` / `MQ_PASSWORD` 后启动服务；
- Linux（systemd）：在 unit 文件中用 `Environment=DB_PASSWORD=xxx` 注入。

### 2.5 启动服务

#### Windows
```cmd
cd D:\lis\deploy-package
start.bat
```
启动成功标志：控制台最后出现 `Started LisMonolithApplication in x.xxx seconds`。

#### Linux
```bash
cd /opt/lis/deploy-package
chmod +x start.sh
./start.sh
```

#### 快速验证
浏览器打开以下地址：
- **前端**：`http://localhost:8080/` → 显示 LIS 登录页（标题「LIS 临床实验室信息系统」）。
- **后端 API**：`http://localhost:8080/api/auth/login` → 返回 JSON（哪怕是 405 Method Not Allowed 也说明后端已起来）。
- 用默认账号 `admin / 123456` 登录 → 成功进入首页。

## 3. 生产环境部署（推荐 systemd / 后台服务）

> 目标：开机自启、崩溃自动重启、独立日志、非 root 用户运行。

### 3.1 创建运行用户与目录

```bash
sudo groupadd -r lis
sudo useradd -r -g lis -s /usr/sbin/nologin -d /opt/lis lis
sudo chown -R lis:lis /opt/lis/deploy-package
sudo mkdir -p /var/log/lis /data/lis/pdf
sudo chown -R lis:lis /var/log/lis /data/lis
```

### 3.2 编写 systemd unit 文件

文件路径：`/etc/systemd/system/lis.service`

```ini
[Unit]
Description=LIS Clinical Lab Information System
After=network.target postgresql.service
Wants=postgresql.service redis.service

[Service]
Type=simple
User=lis
Group=lis
WorkingDirectory=/opt/lis/deploy-package/backend
# 用环境变量注入敏感信息，避免 application.yml 明文
Environment=DB_PASSWORD='你的强密码'
Environment=MQ_PASSWORD='你的MQ密码'
# JVM 参数按服务器内存调整：例如 8G 内存机器
Environment=JAVA_OPTS='-Xms2g -Xmx6g -XX:+UseZGC -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/var/log/lis/heapdump.hprof'
# 启动命令：spring.config.location 指向 yml 绝对路径
ExecStart=/usr/bin/java $JAVA_OPTS -jar /opt/lis/deploy-package/backend/lis-monolith-fresh.jar \
          --spring.config.location=/opt/lis/deploy-package/backend/application.yml
ExecStop=/bin/kill -SIGTERM $MAINPID
Restart=on-failure
RestartSec=10
# 日志
StandardOutput=append:/var/log/lis/stdout.log
StandardError=append:/var/log/lis/stderr.log
# 安全
NoNewPrivileges=true
PrivateTmp=true
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

### 3.3 开机自启 & 运行

```bash
sudo systemctl daemon-reload
sudo systemctl enable lis          # 开机自启
sudo systemctl start  lis          # 立即启动
sudo systemctl status lis          # 查看状态
sudo journalctl -u lis -f          # 实时查看滚动日志
```

### 3.4（可选）Nginx 反向代理 + HTTPS

一体化 JAR 本身可直接对外；当需要 HTTPS / 多域名 / WAF 时，前端用 Nginx 反代：

```nginx
server {
    listen 80;
    server_NAME lis.example.com;
    # HTTP → HTTPS 301
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl http2;
    server_name lis.example.com;

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    client_max_body_size 100M;   # 批量导入 / 附件上传

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;   # 大批量导出 Excel 防止超时
    }
}
```

## 4. 升级部署（已有数据的服务器）

> 原则：**先备份数据库 → 替换 JAR → 执行增量 SQL → 重启服务**

### 4.1 标准操作流程（Linux 示例，Windows 对应改路径即可）

```bash
# 1. 备份数据库
export PGPASSWORD='你的密码'
pg_dump -h localhost -U lis_user lis_db | gzip > /data/backup/lis_db_$(date +%Y%m%d_%H%M%S).sql.gz
# 可选：备份 JAR 和配置（便于回滚）
cp -a /opt/lis/deploy-package/backend/lis-monolith-fresh.jar /data/backup/lis-monolith-$(date +%Y%m%d).jar.bak
cp -a /opt/lis/deploy-package/backend/application.yml  /data/backup/application-$(date +%Y%m%d).yml.bak

# 2. 停止服务
sudo systemctl stop lis

# 3. 替换新 JAR（新部署包中的 backend/lis-monolith-fresh.jar 覆盖旧的）
cp /tmp/new-deploy/backend/lis-monolith-fresh.jar /opt/lis/deploy-package/backend/

# 4. 比对 application.yml 差异，合并新的配置项（不要直接覆盖！避免丢失生产密码）
# diff /tmp/new-deploy/backend/application.yml /opt/lis/deploy-package/backend/application.yml

# 5. 若新版本提供「增量 SQL」（如 alter-1.0-to-1.1.sql），手动执行
# psql -h localhost -U lis_user -d lis_db -f /tmp/new-deploy/db/alter-1.0-to-1.1.sql

# 6. 启动服务
sudo systemctl start lis
sudo systemctl status lis
# 观察日志 30 秒，确认无报错
sudo journalctl -u lis --since "1 min ago" -n 200
```

### 4.2 回滚

若升级出现不可恢复错误：
```bash
sudo systemctl stop lis
# 还原旧 JAR
cp /data/backup/lis-monolith-yyyyMMdd.jar.bak /opt/lis/deploy-package/backend/lis-monolith-fresh.jar
# 如需还原数据库（慎重！确认升级后未产生新业务数据）
# gunzip -c /data/backup/lis_db_xxx.sql.gz | psql -h localhost -U lis_user lis_db
sudo systemctl start lis
```

## 5. 常见故障排除（Troubleshooting）

### 5.1 启动失败：端口占用
```
Web server failed to start. Port 8080 was already in use.
```
解决：
- Windows：`netstat -ano | findstr :8080` → 拿到 PID → `taskkill /F /PID <PID>`；或修改 `application.yml` → `server.port: 8081`。
- Linux：`sudo lsof -i :8080` → `sudo kill -9 <PID>`。

### 5.2 启动失败：数据库连接错误
```
HikariPool-1 - Exception during pool initialization.
org.postgresql.util.PSQLException: Connection to localhost:5432 refused.
```
排查步骤：
1. `sudo systemctl status postgresql` / Windows 服务中查看 PostgreSQL 是否启动。
2. 核对 `application.yml` 中 `url / username / password` 是否与 2.3 步创建的一致。
3. 手动连接测试：
   ```bash
   psql -h localhost -U lis_user -d lis_db -c "SELECT 1"
   ```
   失败 → 登录 `postgres` 超级用户重置密码：`ALTER USER lis_user WITH PASSWORD '新密码';`

### 5.3 登录提示「用户不存在或密码错误」
- 默认账号：`admin / 123456`。
- 如果用了自定义数据库但**没导入 seed 数据**，`lis_user` 表为空。补导入 `db/seed_30_technician.sql`。
- 密码忘记：数据库重置（需 DBA 权限）：
  ```sql
  UPDATE lis_user SET password = '{bcrypt}$2a$10$7JB720yubVSZvUI0rEqK/.VqGOZTH.ulu33dHOiBE8ByOhJIrdAu2' WHERE username = 'admin';
  ```
  （以上 bcrypt 对应明文 `123456`，执行后重新登录）。

### 5.4 登录后刷新子路由 404（如 `http://host:8080/report/technician` 刷新就 404）
原因：Vue Router history 模式，Spring Boot 默认不认识前端虚拟路径。
解决：本部署包 JAR 已内置 `SpaFallbackConfig`，会把 `/api/**` 之外的路径 forward 到 `/index.html`。**请确认使用部署包内的 JAR 启动，不要用开发环境 `mvn spring-boot:run` 的旧编译产物覆盖。**

### 5.5 页面空白 / 前端资源 404
1. 打开浏览器 DevTools（F12）→ Network → 刷新；检查 `index.html`、`/assets/*.js` 是否 404。
2. 若 404：确认 JAR 内包含前端资源（Linux 可 `jar tf lis-monolith-fresh.jar | grep -c 'index.html'`，结果应 ≥1）。
3. 仍异常：请直接报告 JAR 文件版本号 + 浏览器控制台日志截图。

### 5.6 显示中文乱码（标本名、报告备注、项目名中的汉字）
1. 确认 `application.yml` 的 `spring.datasource.url` **末尾** 带了 `?characterEncoding=utf8`。
2. 确认数据库是 UTF-8：
   ```sql
   SELECT datname, pg_encoding_to_char(encoding) FROM pg_database WHERE datname='lis_db';
   -- 应返回 UTF8
   ```
3. Windows 启动脚本已自动 `chcp 65001`（UTF-8 代码页）；Linux 使用默认 UTF-8 locale 即可。

### 5.7 标本核收失败提示「仪器未配置该项目/标本类型」
按【操作文档 → 5.2 仪器配置】为对应仪器补齐：**检验指标 + 标本类型 + 通道码**三要素，之后才能核收。

### 5.8 试剂入库后条码为空
系统硬性规则：入库验收**通过**瞬间自动生成 `RG + 试剂ID + 批号 + 明细ID` 的条码并写回 `lis_reagent_inbound_item.barcode`。
若出现空条码：
1. 先不要删除入库单；查看启动日志搜索关键字 `generate reagent barcode`，应能找到生成语句与异常；
2. 确认「入库验收」按钮实际点击的是 **验收通过** 而不是「保存草稿」。

### 5.9 报告审核通过后试剂库存未扣减 / 审核被异常阻断
当前设计：**库存不足告警不阻断报告审核通过主流程**，仅记录日志。
1. 查看 `/var/log/lis/stdout.log` 或 Windows 控制台搜索 `reagent auto deduction`，可看到扣减结果；
2. 若完全没有扣减记录，核对【检验项目 → 试剂字典】的关联关系。

### 5.10 日志与诊断信息收集
当需要向技术支持反馈问题时，请打包以下内容：
1. 问题步骤描述（复现路径 + 预期 vs 实际）；
2. 浏览器控制台（DevTools Console 全量）+ Network 的失败请求 HAR；
3. 后端日志：
   - Linux：`journalctl -u lis --since "1 hour ago" > lis_issue.log`
   - Windows：控制台复制最近 200 行，或部署包目录下的日志输出
4. 版本号：`backend/lis-monolith-fresh.jar` 的构建时间（`jar tf` 或文件属性）。

## 6. 防火墙与端口开放清单

| 端口 | 协议 | 来源 | 说明 |
| --- | --- | --- | --- |
| 8080 | TCP | 客户端浏览器 / Nginx | HTTP 前后端共用（必开） |
| 9100 | TCP | 仪器设备网络 | 仪器 TCP 双向通讯（仅实验室仪器网段需要，不要对外网开放） |
| 5432 | TCP | 本机 / 应用服务器 | PostgreSQL（对外网建议关闭，仅本机或内网） |
| 6379 | TCP | 本机 | Redis（生产外网必须关闭） |
| 5672 | TCP | 本机 | RabbitMQ（同上） |

**Linux 用 ufw 示例：**
```bash
sudo ufw allow 8080/tcp comment 'LIS Web'
sudo ufw allow from 192.168.10.0/24 to any port 9100 proto tcp comment 'Instruments TCP'
sudo ufw enable
```

**Windows 高级防火墙：**
```powershell
New-NetFirewallRule -DisplayName 'LIS 8080' -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
New-NetFirewallRule -DisplayName 'LIS 仪器 9100' -Direction Inbound -Protocol TCP -LocalPort 9100 -RemoteAddress 192.168.10.0/24 -Action Allow
```

## 7. 安全基线（生产必做）

| # | 检查项 | 操作 |
| --- | --- | --- |
| 1 | 强密码 | `lis_user` DB 密码、管理员密码、MQ 密码 ≥ 16 位，字母数字符号混合 |
| 2 | 默认密码修改 | 首次登录后立即修改 `admin` 密码；禁用演示账号 `tech` / `director` 或重置密码 |
| 3 | HTTPS | 生产使用 Nginx + TLS 1.2+ 证书；禁用 HTTP 明文访问（3.4 示例） |
| 4 | 独立运行用户 | 用 `lis:lis` 非特权用户启动，禁止 root 直接跑 Java（见 3.1） |
| 5 | 备份策略 | 每日 02:00 自动 `pg_dump` 全量备份，保留 ≥ 30 天，异地冷备 |
| 6 | 数据库审计 | 开启 PostgreSQL `pgAudit` 或启用 log_statement = ddl+mod |
| 7 | 定期升级 | 每月跟进 JDK、PostgreSQL、OS 安全补丁 |
| 8 | 文件权限 | `/opt/lis/deploy-package/backend/application.yml` → `chmod 600 lis:lis`，避免泄露 DB 密码 |

## 8. 快速诊断速查表

| 现象 | 可能原因 | 快速命令 |
| --- | --- | --- |
| 访问地址全超时 | 服务没起来 / 防火墙挡住 | `curl -I http://localhost:8080` |
| 登录后立即退出到 /login | Token 过期 / 数据库 user 表无记录 | 重导 seed；`SELECT * FROM lis_user WHERE username='admin'` |
| 首页统计都是 0 | DB 空 / 连错了数据库 | `SELECT count(*) FROM lis_sample_barcode` |
| 质控 / 微生物页面点不开 | 权限未分配 | 用 `admin` 账号验证；再给角色分配菜单 |
| 仪器不上传结果 | 9100 端口未连 / 配置错误 | `telnet <服务器IP> 9100`；再查 通讯日志 |
| 导出报表失败 / 大批量慢 | JVM 堆内存不够 | 调大 `-Xmx` 到可用内存 60% 左右 |
