## 关键技术决策（含推翻的结论，重要）

### 1. C-9「logic-delete 地雷」是误报 —— 已三方交叉印证推翻
架构师主张「所有表无 `deleted` 列 → 任何 remove/page 必报错」，建议给 9 张存量表加列 + `@TableLogic`。**该主张不成立**：
- `logic-delete-field: deleted` 确实全模块 `application.yml` 都配了（reagent 在 L29-30）
- 但全项目 `@TableLogic` **仅 1 处命中**：`lis-service-sample/.../entity/Sample.java:119`
- `init-schema.sql:113` 的 `deleted SMALLINT DEFAULT 0` 正是 `lis_sample`，与上条严格配对

**根因**：MyBatis-Plus 的 `logic-delete-field` 由 `TableInfoHelper` **按实体字段名惰性匹配**，实体没声明该字段时配置完全惰性、不注入任何 SQL。系统长期正常运行本身即是反证。
**真实雷点恰恰相反**：Java 实体声明了 `deleted` 字段但 DB 没建列，才会注入 `AND deleted = 0` 并抛 `column "deleted" does not exist`。
**最终裁决（Q12「全不做」分支）**：14 张新表不建 `deleted` 列、新实体不声明该字段、不挂 `@TableLogic`，存量 9 张表一列不动。逻辑删除语义统一由 `status` 承担（主数据 0停用/1启用，业务单据走各自状态机）。
**若误采纳架构师原方案的后果**：会把已上线的 `deleteById` 从物理删除**静默改成 UPDATE**，生产事故级。

### 2. 缺陷 K（多仓库同批号）的完整修复姿势
原 `uk_lis_reagent_stock_lot(reagent_id, lot_no)` 不含仓库，多仓库上线即 insert 崩溃。修复要点有三层，**缺一层都等于没修**：
1. `DROP INDEX IF EXISTS uk_lis_reagent_stock_lot` + 新建三列 `uk_lis_reagent_stock_lot_wh(reagent_id, lot_no, warehouse_id)`
2. 存量行无仓库归属，必须用 **`warehouse_id = 0` 哨兵值，禁用 NULL** —— PostgreSQL 唯一索引中 `NULL <> NULL`，用 NULL 会让三列唯一索引对所有存量行**静默失效**
3. **仅 UPDATE 已有行不够**，必须连列约束一起钉死：`SET DEFAULT 0` → `UPDATE NULL 为 0` → `SET NOT NULL`，且**必须排在建三列唯一索引之前**。QA 实证：legacy 环境列保持 nullable 时，插 2 行相同 `(reagent_id, lot_no)` + NULL 仓库，`dup_rows_admitted=2`，索引完全没拦住。

### 3. 供应商字符串迁移的三个坑（QA 用合成数据挖出，被真实数据现状掩盖）
库里 `supplier` 字符串实际 0 条，迁移代码路径**从未被执行**，"跑通了"是假象。造数据后暴露：
- **`ROW_NUMBER()` 编号非幂等**：在 `WHERE` 之后求值，每次从 1 重排，重跑撞 `uk_lis_supplier_code`。改为 `MAX(CAST(SUBSTRING(supplier_code FROM 9) AS INT)) + ROW_NUMBER()` 续号，并加正则守卫 `^SUP_MIG_[0-9]+$` 防手工非规范编码把 CAST 搞炸
- **`TRIM()` 只剥 ASCII 空格**：全角空格 U+3000、tab 原样保留，`罗氏诊断` 5 变体裂成 5 条供应商，`roche/Roche/ROCHE` 裂成 3 条
- **`supplier_name` 无唯一索引**：与手工录入重名时回填绑到优化器选的**任意赢家，全程无报错**

**合并解法（比"迁移前清洗"更彻底）**：定义 `fn_supplier_name_norm()` IMMUTABLE 函数（`[[:space:]]|U+00A0|U+3000` 连续空白折叠为**单个空格**而非全删 + BTRIM + LOWER），用它同时建**表达式唯一索引**和做匹配。数据库层自动生效，界面新建也管得住，不依赖应用自觉。`supplier_name` 列仍存**原始串**，页面展示不变小写。
折叠为单空格而非全删是关键：避免 `"北京 生物"` 与 `"北京生物"` 被误合并（已实测确认不误合）。
