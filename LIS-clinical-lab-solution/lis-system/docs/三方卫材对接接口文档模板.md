## 1. 对接概述

双方采用 **HTTP + JSON** 的方式双向对接，覆盖四类业务：

| 序号 | 业务 | 方向 | 说明 |
| --- | --- | --- | --- |
| 1 | 采购订单下发 | 我方 → 对方 | 我方下单后把订单（含明细）推送对方，回写对方单号 |
| 2 | 商品主数据同步 | 我方 ← 对方 | 我方主动拉取，用于维护商品编码映射 |
| 3 | 供应商主数据同步 | 我方 ← 对方 | 我方主动拉取，新增/更新本地供应商档案 |
| 4 | 库存与效期查询 | 我方 ← 对方 | 按试剂编码实时查询对方库存、批号、效期 |
| 5 | 到货回传 | 对方 → 我方 | 对方发货/到货后回传，我方生成**待验收**入库单 |
| 6 | 订单状态回传 | 对方 → 我方 | 对方回写订单状态与对方单号 |
| 7 | 订单查询 | 对方 ← 我方 | 对方按需拉取我方未取消的采购订单 |
| 8 | 试剂主数据查询 | 对方 ← 我方 | 对方按需拉取我方启用的试剂档案 |

适配原则：**对方接口字段与本文标准字段不一致时，只调整「字段映射」配置（第 7 章），不改代码、不重新发版。**

## 2. 公共约定

| 项 | 约定 |
| --- | --- |
| 协议 | HTTP/1.1，建议 HTTPS |
| 方法 | 查询 `GET`，新增/推送 `POST` |
| 报文格式 | `application/json; charset=UTF-8` |
| 字符集 | UTF-8（中文不得使用 GBK 转义） |
| 时间格式 | `yyyy-MM-dd`（日期）、`yyyy-MM-dd HH:mm:ss`（时间） |
| 金额 / 数量 | JSON 数字，最多 4 位小数，不使用千分位字符串 |
| 编码 | 订单号、试剂编码、商品编码均为字符串，不做前导零截断 |
| 空值 | 无值字段传 `null` 或直接省略，不传 `"-"`、`"N/A"` |
| 幂等 | 到货回传按 `deliveryNo` 幂等；订单状态回传按 `orderNo` 覆盖更新 |
| 超时 | 连接 10s，读超时默认 10s（可在对接配置中调整） |
| 重试 | 非 2xx 或网络异常时按配置重试（默认 0 次） |
| 分页 | 拉取类接口我方不分页，单次取上限：订单 500 条、试剂 2000 条、商品/供应商全量 |
| 日志 | 双方请求/响应报文留痕，正文超过 20000 字符截断 |

## 3. 鉴权约定

### 3.1 我方调用对方（出站）

我方支持 4 种鉴权方式，由「三方卫材对接配置」中的 `authType` 选择，**请对方在本表勾选并提供参数**：

| 方式 | authType | 需要的参数 | 对方是否支持 |
| --- | --- | --- | --- |
| 无鉴权（仅内网/IP 白名单） | 0 | 对方出口 IP 白名单：`【待填写】` | ☐ |
| 自定义请求头 Token | 1 | 请求头名 `【待填写，默认 Authorization】`、Token 值 `【待填写】` | ☐ |
| AK/SK 签名（HMAC-SHA256） | 2 | AppKey `【待填写】`、AppSecret `【待填写】` | ☐ |
| HTTP Basic | 3 | 用户名 `【待填写】`、密码 `【待填写】` | ☐ |

**AK/SK 签名算法（固定，请对方按此校验）**

- 请求头：`X-App-Key`、`X-Timestamp`（毫秒时间戳）、`X-Sign`
- 待签名字符串：`HTTP方法 + "\n" + 路径 + ["?" + 查询串] + "\n" + 时间戳 + "\n" + 请求体原文`
  - 路径为 URL 的 path 部分（不含域名），无查询参数时该段为空
  - GET 请求的请求体按空字符串参与签名
- `X-Sign = Base64(HmacSHA256(AppSecret, 待签名字符串))`

签名示例：

```
待签名 = GET\n/api/stock?reagentCode=RG001\n1730160000000\n
X-Sign = Base64(HmacSHA256("【AppSecret】", 待签名))
```

### 3.2 对方调用我方（入站）

- 请求头必须携带：`X-Third-Token: 【我方下发】`
- 我方为该对接方分配 `partnerCode`：`【我方填写，如 VENDOR_A】`
- 入站接口需在对接配置中开启「入站开关」，否则返回「对接方未开放入站接口」
- Token 建议通过线下/加密渠道传递，不要出现在 URL 或日志中

## 5. 出站接口（我方调用对方）

### 5.1 采购订单下发

- 方法 / 路径：`POST 【待填写】`
- 触发时机：我方采购订单「下单」后，在订单页面点击「推送卫材」
- 业务约束：已取消（状态 4）的订单不允许推送
- 幂等建议：对方以 `orderNo` 去重，重复推送返回同一对方单号

**请求体（默认标准格式）**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| orderNo | String | 是 | 我方采购订单号，全局唯一 |
| supplierName | String | 是 | 供应商名称 |
| deptName | String | 否 | 请购科室 |
| orderDate | String | 是 | 下单日期 `yyyy-MM-dd` |
| expectDate | String | 否 | 期望到货日期 `yyyy-MM-dd` |
| totalAmount | Number | 是 | 订单总金额 |
| remark | String | 否 | 订单备注 |
| operatorName | String | 否 | 操作人 |
| items | Array | 是 | 明细，至少一条 |
| items[].reagentCode | String | 是 | 我方试剂编码 |
| items[].reagentName | String | 是 | 试剂名称 |
| items[].specification | String | 否 | 规格 |
| items[].quantity | Number | 是 | 采购数量 |
| items[].unit | String | 否 | 单位 |
| items[].unitPrice | Number | 否 | 单价 |
| items[].amount | Number | 否 | 金额 = 数量 × 单价 |
| items[].remark | String | 否 | 明细备注 |

```json
{
  "orderNo": "PO202610290001",
  "supplierName": "某医疗器械有限公司",
  "deptName": "检验科",
  "orderDate": "2026-10-29",
  "expectDate": "2026-11-05",
  "totalAmount": 12800.00,
  "remark": "常规补货",
  "operatorName": "张三",
  "items": [
    {
      "reagentCode": "RG001",
      "reagentName": "总胆红素测定试剂盒",
      "specification": "R1:60mL×2 R2:20mL×1",
      "quantity": 10,
      "unit": "盒",
      "unitPrice": 1280.00,
      "amount": 12800.00,
      "remark": ""
    }
  ]
}
```

**响应体**

我方按 `data` → `result` → 根节点 的顺序脱壳，依次尝试 `remoteOrderNo`、`orderNo`、`orderId`、`billNo`、`id` 取对方单号，取到后回写到我方订单。响应字段名不一致时通过字段映射调整。

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "remoteOrderNo": "VD20261029001",
    "acceptTime": "2026-10-29 10:30:00"
  }
}
```

**失败约定**：HTTP 非 2xx 或无法解析视为失败，我方界面提示错误并写入「卫材接口日志」。

## 6. 入站接口（对方调用我方）

统一约定：

- 基础路径：`/api/reagent/open/thirdparty/{partnerCode}`
- 请求头：`Content-Type: application/json; charset=UTF-8`、`X-Third-Token: 【我方下发】`
- 返回结构：`{ "code": 200, "message": "success", "data": {...} }`
- **注意**：业务校验失败时 HTTP 状态码仍为 `200`，需以响应体 `code` 判断成败（`200` 成功，`400/500` 失败）

### 6.1 到货回传

- 方法 / 路径：`POST /api/reagent/open/thirdparty/{partnerCode}/delivery`
- 处理逻辑：生成**待验收**入库单（不跳过验收），检验人员在我方「入库验收」页面确认后正式入库
- 明细商品编码必须已在「卫材商品映射」中建立对应关系，否则整单拒绝

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| deliveryNo | String | 是 | 对方送货单号（幂等键） |
| orderNo | String | 否 | 我方采购订单号，匹配后自动关联订单与供应商 |
| supplierName | String | 否 | 供应商名称 |
| items | Array | 是 | 到货明细 |
| items[].remoteCode | String | 是 | 对方商品编码（兼容 `reagentCode`/`code`/`productCode`/`goodsCode`/`skuCode`） |
| items[].lotNo | String | 是 | 批号（兼容 `batchNo`/`lot`） |
| items[].quantity | Number | 是 | 到货数量，必须 > 0（兼容 `qty`/`amountQty`） |
| items[].unit | String | 否 | 单位 |
| items[].purchasePrice | Number | 否 | 单价（兼容 `unitPrice`/`price`） |
| items[].expiryDate | String | 否 | 有效期至 `yyyy-MM-dd`（兼容 `expireDate`/`validUntil`） |
| items[].location | String | 否 | 库位（兼容 `storageLocation`） |
| items[].remark | String | 否 | 备注 |

明细数组也可放在 `data.items`、`items`、`details`、`deliveryItems` 下。

```json
{
  "deliveryNo": "DN20261029001",
  "orderNo": "PO202610290001",
  "supplierName": "某医疗器械有限公司",
  "items": [
    {
      "remoteCode": "VD-RG-0001",
      "lotNo": "20260901",
      "quantity": 10,
      "unit": "盒",
      "purchasePrice": 1250.00,
      "expiryDate": "2027-09-01",
      "location": "冷藏库A"
    }
  ]
}
```

**成功响应**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "inboundId": 1024,
    "inboundNo": "RK202610290001",
    "itemCount": 1
  }
}
```

**失败响应示例**

```json
{
  "code": 500,
  "message": "以下对方商品编码未建立映射，无法入库: VD-RG-9999",
  "data": null
}
```

### 6.2 订单状态回传

- 方法 / 路径：`POST /api/reagent/open/thirdparty/{partnerCode}/order-status`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| orderNo | String | 是 | 我方采购订单号（兼容 `purchaseOrderNo`） |
| remoteOrderNo | String | 否 | 对方单号（兼容 `thirdOrderNo`/`supplierOrderNo`） |
| status | Integer | 否 | 订单状态，取值 0–4，见下表（兼容 `orderStatus`） |

我方订单状态字典：

| 值 | 含义 |
| --- | --- |
| 0 | 待下单 |
| 1 | 已下单 |
| 2 | 部分到货 |
| 3 | 已到货 |
| 4 | 已取消 |

若对方回传的是中文字符串，我方按关键字识别：含「取消」→ 4；含「到货」或「完成」→ 3；含「发货」或「部分」→ 2；含「下单」→ 1。建议直接回传数字。

```json
{
  "orderNo": "PO202610290001",
  "remoteOrderNo": "VD20261029001",
  "status": 3
}
```

```json
{
  "code": 200,
  "message": "success",
  "data": { "orderNo": "PO202610290001", "status": 3 }
}
```

## 9. 联调与验收

### 9.1 联调前置

1. 我方在「三方对接 → 三方卫材对接」新增配置：`baseUrl`、鉴权方式、四个业务路径、入站 Token，并启用

4. 双方 IPv4/域名互通，防火墙放通我方出站与对方入站（默认端口 8092）

### 9.2 联调用例清单

### 9.3 日志与排障

- 我方「三方对接 → 卫材接口日志」可按对接方、业务类型、方向（出站/入站）、成功/失败、关键字检索
- 每条日志记录：方法、完整 URL、请求体、响应体、HTTP 状态、耗时（出站）、错误信息
- 排障顺序：先看日志 `success=0` 的记录与 `errorMsg`，再核对字段映射（路径写错、数组层级写错最常见）

### 9.4 快速验证命令（curl）

> 把 `{partnerCode}` 换成我方分配的对接方编码，`{token}` 换成入站 Token。

```bash
# 1) 到货回传
curl -s -X POST "http://<LIS服务器IP>:8092/api/reagent/open/thirdparty/{partnerCode}/delivery" \
  -H "Content-Type: application/json; charset=UTF-8" \
  -H "X-Third-Token: {token}" \
  -d '{"deliveryNo":"DN20261029001","orderNo":"PO202610290001","items":[{"remoteCode":"VD-RG-0001","lotNo":"20260901","quantity":10,"purchasePrice":1250.00,"expiryDate":"2027-09-01"}]}'

# 2) 订单状态回传
curl -s -X POST "http://<LIS服务器IP>:8092/api/reagent/open/thirdparty/{partnerCode}/order-status" \
  -H "Content-Type: application/json; charset=UTF-8" \
  -H "X-Third-Token: {token}" \
  -d '{"orderNo":"PO202610290001","remoteOrderNo":"VD20261029001","status":3}'

# 3) 拉取我方订单
curl -s "http://<LIS服务器IP>:8092/api/reagent/open/thirdparty/{partnerCode}/orders?status=1" \
  -H "X-Third-Token: {token}"

# 4) 拉取我方试剂
curl -s "http://<LIS服务器IP>:8092/api/reagent/open/thirdparty/{partnerCode}/reagents" \
  -H "X-Third-Token: {token}"
```
